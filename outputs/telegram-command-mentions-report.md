## Root cause

_routing_text() only recognized an exact command token such as /tasks. Telegram's @bot_username suffix made the token different, so the generic handler did not route it to the planner.

## Approved fix

Added one shared registered-command list, normalized own-bot mentions before orchestration, ignored known commands addressed to other bots, and reused the list for the Telegram command menu.

**Why this is causal:** The generic handler now converts /tasks@familyhealtheee_bot to /tasks before domain routing, while the handler exits before authorization and orchestration for a different bot mention.
