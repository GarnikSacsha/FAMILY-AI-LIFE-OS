## Root cause

The optional-currency multiline pattern required each line to begin with an amount, so the 'Запиши' prefix hid the first item. Separately, the summary worker unconditionally created and delivered conversation-kind summaries after the idle threshold.

## Approved fix

Normalize known expense command prefixes before parsing each line, and restrict proactive summary delivery to daily summaries only.

**Why this is causal:** Prefix normalization exposes the hidden first amount to the existing validated line parser. Removing conversation-kind summaries from the delivery path prevents both new and previously pending idle recaps from reaching Telegram.
