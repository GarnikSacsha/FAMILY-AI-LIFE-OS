**Побайтовое соответствие файлов контейнера этой ревизии пока не подтверждено.**
SSH и файловый интерфейс Railway SFTP недоступны из текущей среды: соединение
с `ssh.railway.com` завершается тайм-аутом. Публичный API не предоставляет
выгрузку содержимого исходников/образа. Диапазоны зависимостей в `pyproject.toml`
не заменяют список фактически установленных пакетов контейнера.

Это различие сохранено явно: исходники восстановлены по ревизии Railway,
но точный файл-за-файлом снимок контейнера не выдан за полученный результат.
Для завершения проверки подготовлен `scripts/attest_runtime.py`: он печатает
хеши runtime-исходников и версии пакетов, не импортируя приложение и не читая
окружение или секреты. Его нужно выполнить **в существующем контейнере** через
доступное соединение, затем сравнить JSON с восстановленной базой.
Локальный запуск не подтверждает состав production.

Октябрьские deployments `2215a6be-4cc1-43ab-a59a-c6cad9945f7e` и
`4415237c-7797-4adb-b3b6-91d345d1831a` использовали другой образ:
`sha256:9124fb77bd61758636d4d4498f9bae2233b24a3bdb1c1de20afbb1841bb5083d`.
Поэтому локальный `oura-strict-release` не объявлен копией нынешнего контейнера.

## Какие доработки включены

| Источник | Что перенесено |
|---|---|
| Git `3312fa3` | Текущая записанная база: расходы, календарь, почта, Oura, управление задачами/покупками, надёжность worker |
| Локальная `main` / `5a3f9bc` | Проверка сумм и дат расходов, английские формулировки, безопасность текста Sheets, сохранение UTC при SQLite; исходные regression tests |
| `oura-strict-release` и соответствующие tests из `oura-fix` | Архив и история здоровья, понятные подписи метрик, LLM-объяснения, строгая JSON-схема и ограниченное восстановление после ошибок формата |
| Основной dirty worktree | Google OAuth recovery и понятные действия при потере доступа, публичные страницы, завершение семейных задач обычным сообщением |
| Предыдущий этап уборки | Карта проекта, инструкции Sheets/релизов, инвентаризатор, исключения Docker-контекста |

Переносы выполнялись трёхсторонним слиянием либо выбором конкретной функции.
Это сохранило календарь, пагинацию, кнопки управления и retry-цикл Sheets из
базы `3312fa3`, которые исчезли бы при копировании старых файлов целиком.

При объединении разрешены два пересечения маршрутизации:

- Фраза «Купил продукты за 100 грн» остаётся расходом и не завершает похожую
  задачу. Добавлен тест с реальной локальной SQLite и pending confirmation.
- Уточнение времени «В 10:00, … и готово» продолжает уже начатый календарный
  диалог. Существующий календарный regression test сначала выявил конфликт,
  затем прошёл после исправления приоритета.

Изменений зависимостей, миграций или архитектуры при объединении не потребовалось.

## Что сохранено отдельно

Bitrix24, demo-режим, незавершённая health-platform и старый эксперимент
telegram-context-repro не включены в активное приложение. Их исходники,
тесты и документы сохранены в первоначальных каталогах и в копиях безопасности.
Особенно важно не переносить автоматически альтернативную миграцию `010`
из context-repro.

Соседний каталог `family-consolidation-20261109` содержит:

- `originals/`: 1 096 файлов исходного кода, тестов и документации с проверкой
  хешей после копирования; это выбранные файлы, а не копия всех пользовательских данных.
- `preservation-manifest.json`: пути, исходные ветки/HEAD, Git-статусы и хеши.
- `deployed-source-3312fa3/` и `deployed-source-manifest.json`: восстановленная
  Git-база сборки.
- `live-deployment-evidence.json`: разрешённые поля метаданных трёх deployments,
  без переменных окружения и секретов.
- `applied-sources.json`: журнал основных переносов; окончательный состав
  объединения зафиксирован в Git diff/коммите и итоговом манифесте.

В этой ветке `outputs/` исключён из Git: там находятся только локальные
результаты проверок. Проверяемые манифесты и отчёт сохранены в `docs/operations`.

Секреты, `.env`, содержимое `outputs/`, базы и кэши не копировались. Они остались
в исходных местах. Архивы и медиакаталоги не удалялись и не перемещались.
