# Google Sheets: смена месяца и восстановление

Проверено по существующему коду и аудиту рабочего сервиса 2026-11-09.
После восстановления пользователь подтвердил, что всё обновилось. Отдельную
повторную сверку всех ноябрьских строк после его изменений агент не выполнял.

## Как устроен перенос

```text
Telegram → финансовая запись PostgreSQL → фоновый worker
         → служебная вкладка __family_ai_sync_receipts
         → формулы видимой вкладки бюджета
```

Первичное хранилище — PostgreSQL. Оба пользователя записывают расходы туда;
очистка таблицы не удаляет финансовые записи из базы.

При `GOOGLE_SHEETS_LAYOUT=monthly_budget` worker выбирает расходы в UAH
за `GOOGLE_SHEETS_PERIOD`, с границами месяца по `Europe/Kyiv`. Имя файла и
видимое название месяца не определяют выборку.

| Настройка Railway | Смысл |
|---|---|
| `GOOGLE_SHEETS_SPREADSHEET_ID` | ID файла из адреса `/spreadsheets/d/<ID>/edit` |
| `GOOGLE_SHEETS_MONTHLY_SHEET_ID` | Числовой `gid` нужной видимой вкладки |
| `GOOGLE_SHEETS_PERIOD` | Месяц в формате `YYYY-MM`, например `2026-12` |
| `GOOGLE_SHEETS_LAYOUT` | `monthly_budget` для текущего шаблона бюджета |

Права редактирования нужны сервисному аккаунту бота. Доступ личного Google
аккаунта и доступ бота могут отличаться. Секреты и JSON ключа в документацию
не копировать.

## Обычная смена месяца

1. Сохранить старую таблицу как историю. Подготовить отдельный файл из шаблона
   следующего месяца, сохранив заголовки категорий, формулы итогов и сетку дней.
2. Если шаблон копировался с рабочего бюджета, проверить также служебную вкладку
   `__family_ai_sync_receipts`: в новом файле не должно быть расходов прошлого
   месяца. Пустые видимые суммы этого не доказывают. Очистку данных выполнять
   только в подтверждённом новом файле, сохраняя старую историю.
3. Проверить доступ сервисного аккаунта, ID нового файла и `gid` вкладки.
4. Подготовить **вместе** ID файла, ID вкладки и `GOOGLE_SHEETS_PERIOD`.
   Не применять новый файл с оставшимся старым месяцем даже временно.
5. С явным разрешением на применение настроек выпустить изменение в существующий
   сервис `powerful-exploration / FAMILY-AI-LIFE-OS / production`. Использовать
   ту же проверенную сборку; смена месяца не требует загрузки локального кода.
6. Дождаться завершения переноса, затем проверить ID, даты, суммы и статусы
   финансовых записей за новый месяц, а не только общую сумму.

Интервал опроса worker в проверенном коде — 5 секунд, но каждая запись требует
нескольких обращений к Google. Фиксированный короткий срок завершения не гарантируется.

## Служебная вкладка и формулы

`__family_ai_sync_receipts` содержит UUID расхода, день, категорию, сумму и
период в колонках `A:E`; `F1:G1` содержит версию шаблона и отметку периода.
Вкладка может быть скрыта или открыта пользователем. Период при чтении без
форматирования может выглядеть как числовая дата Google Sheets.

Текущие формулы `B3:K33` суммируют служебные записи **по дню и категории**,
без фильтра по месяцу. Поэтому отдельный файл должен содержать расходы одного
месяца. Добавление ноября поверх сохранённых октябрьских строк смешает суммы.

Нельзя ограничиваться очисткой видимой сетки: записи могут остаться в `A:E`,
а формулы — быть стёрты. Маркер в `F1:G1` позволяет коду пропустить повторную
установку шаблона; ручная очистка формул при сохранённом маркере может потребовать
отдельного восстановления шаблона.

## Если перенос не начался или попал другой месяц

| Симптом | Что прочитать первым |
|---|---|
| В новой таблице прошлый месяц | Значение `GOOGLE_SHEETS_PERIOD` в применённой конфигурации |
| Расходы есть в боте, а в Sheets пусто | Записи PostgreSQL за нужный месяц, `sheets_sync_status`, попытки, ошибки и ключ проекции |
| Суммы смешались | Служебные строки `A:E`, их периоды и UUID; наличие старого месяца |
| После очистки ничего не возвращается | Ключ проекции и статус `synced`; очистка ячеек не обязательно ставит записи в очередь заново |
| Ошибка доступа или вкладки | Доступ сервисного аккаунта, фактический ID файла, `gid` и заголовки |

Ключ проекции включает файл, `gid`, месяц и версию шаблона. При изменении цели
worker может повторно перенести уже синхронизированные записи выбранного месяца.
UUID защищает от повторного добавления в служебной вкладке. Не нужно заново
создавать расходы в боте или массово сбрасывать статусы базы.

Если цель не изменилась, а уже синхронизированные строки стёрты, сначала
составить точный список отсутствующих UUID и план восстановления. Любые
изменения данных выполнять отдельно после согласования; не запускать старые
скрипты исправлений из `outputs/` вслепую.
